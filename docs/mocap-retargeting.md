# Mocap and reviewed retargeting — M3

The M3 adapter transfers a reviewed FK skeleton to a differently named FK skeleton using evaluated source orientations and explicit rest-pose compensation. It never renames bones, flattens a rig, bypasses constraints, or edits the original source/target Actions. This is a bounded adapter with exact preconditions, not a claim of compatibility with every commercial rig.

## Tools and lifecycle

- `production.mocap_analyze`: hierarchy, bone/channel counts, sampled root motion, FPS, rest-pose heuristic, missing channels, small alternating-motion candidates, unusual physical height, translation candidates, semantic and F-Curve analysis. Source Action remains active and unchanged.
- `production.mocap_map_skeleton`: combines source and target semantic evidence or validates explicit rows. Each row contains `source_bone`, `target_bone`, `semantic_role`, `confidence`, and `evidence`. Approval is separate from inference.
- `production.mocap_preview_retarget`: with source/target/options returns an immutable proposal; with its `operation` path creates a checkpoint and a new preview Action, numerically evaluates it, and restores the previous target assignment. Candidate is retained for visual comparison and recovery.
- `production.mocap_retarget`: `analyze → propose → preview → apply → verify → revert` through the common M3 transaction layer. `apply` creates another new Action and assigns it only after numeric verification. Visual acceptance remains required.
- `production.mocap_cleanup`: defaults to read-only analysis and `apply=false`. Choose one reviewed M2 correction strategy per immutable proposal: curves, quaternion representation, root motion or compatible IK contacts. Apply additionally requires `apply=true`; no unattended sequence of edits.

Required roles: root, pelvis, spine, head and upper/lower/end bones of both arms and legs (`left_upper_leg`, `left_lower_leg`, `left_foot`, etc.). Neck/toe/twist/helper roles are optional semantically but this conservative retarget adapter requires every actual source and target bone mapped one-to-one, with matching mapped parent relationships. A target with additional twist joints therefore needs an explicit specialized adapter; it is not silently flattened.

`mapping_approved=true` means a user/agent has reviewed the correspondence. It does not bypass the confidence floor. Since M3.1 (AUD-003) **confidence is computed by the server**, never taken from the caller: hierarchy consistency through the nearest mapped ancestor, a body frame (pelvis→head up axis and the average foot direction), geometric left/right side, central-role alignment and bone-length proportion. A caller-supplied `confidence` can only lower the computed value (`caller_hint_used_as`). Rows below 0.9, and structural conflicts, are refused with `CONFIDENCE_NOT_COMPUTED`, `LOW_CONFIDENCE_MAPPING`, `SIDE_MISMATCH`, `HIERARCHY_CONFLICT`, `CENTRAL_ROLE_LATERAL` or `PROPORTION_OUTLIER`. Measured: the auditor's left/right swap, previously validated and applied, is refused with 6 `SIDE_MISMATCH` rows. Source/target Actions, rest matrices, hierarchy, solver settings, transform state, FPS and units are fingerprinted into the proposal. Any change invalidates it before candidate allocation. Unknown, partial or low-confidence mappings cannot retarget.

## Supported adapter

Local unparented armature objects; aligned object orientations; positive uniform object scale; unconstrained FK bones with normal inheritance; one active Action slot/layer/strip; no active NLA, drivers, linked overrides, channel modifiers or unsupported animated RNA settings. Source needs an active Action; target may be unanimated. Quaternion and Euler bone rotation modes are supported; axis-angle fails closed. Animated source scale/shear and translations outside mapped root/pelvis require another adapter. No implicit transform application occurs.

The target Action is **new**, even if target already has animation. All target pose transform channels are keyed at the requested range and step. Existing Actions and target rotation modes stay intact. New key interpolation is LINEAR; source Bézier motion can be sampled, but the candidate must meet dense verification tolerances and may be rejected when sampling is too coarse.

For each bone, the target armature-space orientation is `source_pose_rotation × inverse(source_rest_rotation) × C × target_rest_rotation`, where `C` rotates the target rest bone direction onto the source rest direction (identity for identical rests, root and pelvis). Before any checkpoint, each bone is classified `identical`, `compensated` (≤ `rest_compensation_max_degrees`, default 60°), `incompatible` (`REST_POSE_INCOMPATIBLE`) or `convention` (root/pelvis); body frames differing by more than 10° are also refused. v0.3.0 omitted `C`: a T-pose source arm landed 19.29° off on an A-pose target while verification passed. Derivation, thresholds and evidence: [retarget-math](retarget-math.md). The target hierarchy and lengths determine joint positions. Root translation is scaled by the median mapped bone-length ratio (`scale_mode=skeleton`) or explicit positive physical-distance `scale_factor` (`scale_mode=explicit`, compensated for different uniform object scales). `root_motion=preserve` transfers displacement; `in_place` fixes horizontal root displacement to its first sampled value while preserving vertical motion. Pelvis basis translation includes the animated parent orientation when converting through source rest axes; rest compensation and resulting positions are verified numerically. Root displacement reports use world XYZ in metres.

## Validation and measurements

Bake range: maximum 1001 integer frames, sampling step 1–4, maximum 60000 bone/frame samples per internal pass. Samples are processed inside Blender; no frame-by-frame MCP calls. Verification includes every baked frame and its midpoint, and (M3.1) measures in world space the angle between each source and target bone direction (`POSE_CORRESPONDENCE_FAILED`), bend-plane flips and limb events introduced by the retarget (`INTRODUCED_LIMB_EVENTS`). The per-pass sample budget, the payload size and a coarse runtime/memory estimate are checked at propose time (`capacity`), before any checkpoint. Source and target armatures in `pose_position=REST` are refused (`POSE_POSITION_REQUIRED`). Default tolerances: 0.1 mm position and 0.05° orientation; configurable up to 1 cm/1° conservative ceilings. Report maximum/mean errors, sample count, key count and untouched source state.

Every retarget verification also measures source and target contacts/sliding, root displacement/distance, limb stretch, abrupt flexion candidates and motion derivatives. Contact defaults are explicit: configured horizontal ground plane, bone-head height tolerance 3 cm, vertical speed 0.3 m/s, sliding tolerance 1 cm. These point contacts are an initial retarget QA pass; use M3 geometry contacts with reviewed heel/sole/toe offsets for final surface validation. Limb-pop threshold defaults to 25° between samples and is configurable; it is an issue candidate, not a claim that intentional impacts are errors. A target pop must correspond to the same source limb/frame without exceeding its magnitude by more than twice the angular verification tolerance. More than 32 events in either report fails the conservative verification budget; shorten the reviewed range. Joint length excess over 1% fails the strict no-stretch adapter. A retarget may preserve a source sliding defect: it reports the defect and requires reviewed contact correction, not silently changes locomotion.

Output lists are bounded; full mapping and operation state remain local in the immutable proposal. Artifacts include source fingerprints, candidate fingerprint, checkpoint manifest, exact options, before/after measurements and append-only operation events. A timeout is uncertain execution: inspect evidence and checkpoint rather than retrying automatically.

## Cleanup

Curve cleanup delegates to the tested M2 `ANALYZE → PROPOSE → PREVIEW → APPLY → VERIFY` engine. Jitter smoothing requires `strategies=["mocap_smoothing"]`, `allow_smoothing=true`, an explicit native-channel tolerance, and a reviewed channel selection. Scalar cleanup excludes quaternion components; quaternion continuity uses the orientation-preserving quaternion tool. Redundant keys, obvious spikes and root/contact changes are separate operations with their own error bounds and guards. `strategy=contact_lock` dispatches to the M3 reviewed surface/heel/sole/toe adapter with its complete mapping, phase and knee-pop safeguards; it does not infer foot markers or contacts automatically. Fast or alternating motion is only a candidate; analysis never deletes it.

## Reproduction

`tests/blender/m3_mocap_fixtures.py` creates two differently named 19-bone skeletons, a 1.2-scale target with A/T rest-arm mismatch, procedural skinned proxy meshes, root motion, deliberate foot sliding and a separate noisy Action. No external assets or production files are used. `tests/blender/m3_mocap_probe.py --blender <installed executable>` exercises mapping, preview/apply/verify/revert, original preservation, stale/low-confidence rejection, root transfer, bounded cleanup, geometry/deformation QA and equivalent multiview renders under real Blender and the unmodified safe-mode validator. Numerical correspondence is not artistic certification.

Verified evidence: `test-artifacts/m3m-eb91942b/report.json` contains 32 passing real-Blender checks, including geometry contacts, full limb QA, deformation sampling and 18 equivalent before/after renders (frames 1, 9, 17; FRONT/SIDE/THREE_QUARTER). `coordinate-check.json` adds five world-coordinate/object-scale checks. The 779 bone/frame correspondence samples measured maximum position error 3.4774512056843524e-7 m and rotation error 2.530858900355895e-5°; root motion 0.20000000298023224 m becomes 0.24000003933906555 m at scale 1.2. Geometry phase-local sliding remains 0.22800002659412696 m and is explicitly reported. The initial/whole-stance bone-head metric is 0.24000003674377715 m; the shorter geometry phase resets its origin after FOOT_FLAT, explaining the difference.

Cleanup changes 19 noisy scalar keys within maximum deviation 0.0004000067710876465 native units, below the explicit 0.0005 tolerance. Deformation QA samples 13 proxy meshes/338 vertices, 39 evaluations, zero detected collapse/stretch issues; this intentionally simple proxy does not prove anatomical quality. End-to-end retarget including checkpoint/verification took 8887.706 ms; geometry contacts 133.459 ms; mocap analysis 3148.455 ms; public retarget report 6430 bytes on this machine. `visual-review.json` records actual inspection and limitations. All original Actions and original fixture file hash were preserved. No production assets were involved.

During validation, equivalent quaternion signs initially inflated the reported rest mismatch to 360°. This reporting defect was fixed using the shortest quaternion angle via `atan2` and checked independently with the relative rotation matrix trace. The actual maximum rest-frame compensation is 27.215523760915218°, including bone roll. The same robust measure retains small floating-point verification errors instead of rounding them to zero. A separate 90° animated-parent test verifies the pelvis translation against analytically expected world X/Y values.

Cross-review also identified two coordinate issues, now fixed and measured: the read-only analyzer samples evaluated object transforms at every frame (an animated object translation contributes the expected 0.3 m), and `in_place` projects through world axes before locking XY. With both armatures tilted 90° around X, the verification preserves -0.1 m of world vertical travel while eliminating world horizontal travel. Constant aligned object orientations and different uniform object scales are tested independently. The retarget adapter still refuses animated object transforms; the analyzer can measure them without pretending they are safe to mutate.
